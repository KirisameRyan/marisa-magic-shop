# 条件单、游客保存与交易所指南

## 交付范围

- 游客凭证与当前登录分开保存在浏览器。切换账户不删除游客凭证；有效期30天，访问验证时剩余不足7天会续期并轮换凭证。清理浏览器、跨设备或超过有效期仍可能无法恢复，不承诺永久匿名登录。

- 系统正常双边报价的买一卖一差0.1，深层档位可空档，数量不再三角递增。报价中心随现价、库存、估值和玩家委托压力调整，主动订单混合价值、趋势与随机倾向；仍受真实模拟现金与库存上限约束。
- 新增条件单页面：止盈止损、MACD形态、反弹买入、回落卖出。每账户最多20条监控中订单，历史保留最多约80条。

## 条件单规则

止盈止损按创建时持仓成本固定触发价格，支持价格与百分比；多空方向对称，比例指价格变化而非保证金收益率。同一组先触发的一方生成委托，另一方不再执行。创建时拒绝已经满足的止盈止损。卖出或普通平仓的保护数量不能超过未被其他保护或退出委托占用的数量。手动退出优先，随后按创建顺序缩减保护数量，清仓或反向则取消保护。监控不冻结买入资金，触发时按实际资金与仓位限制校验。

MACD固定12/26/9，支持1/5/15/30分钟、1/4小时、日线。按与图表一致的北京时间周期聚合，仅使用已完成K线，至少35根后启用。金叉与死叉比较DIF与DEA的前后关系；二次交叉默认30根窗口，中间必须出现反向交叉，可设3至100根。零轴过滤检查DIF、DEA同时零上或零下。顶底背离比较相邻两个严格确认高低点与对应DIF，左右各2根确认，转折点相距至多60根；第二点确认时才发信号。形态只监测创建后的新信号。

反弹买入跟踪最低成交价，回落卖出跟踪最高成交价，幅度可用百分比或价差。可选先跌/先涨的百分比激活条件，0为直接跟踪，参考价在创建时固定。每分钟只观察实际最新成交价，不推测分钟内路径。

触发在本批撮合与风险处理完成后判定，委托 submittedAt 为本批时间+1毫秒，最早下一分钟参与撮合。限价可不成交；对手价为带最大滑点限制的限价委托，不越过保护价格。失败显示原因，不无限重试，不回填过去的转折点成交。停牌期间继续保留条件，恢复后判断。触发后可以在“我的委托”撤销未成交数量，条件单本身不重复触发。

## 历史与性能

各标的各周期独立保存EMA状态、最近最多300根指标K线和形成中的聚合K线，不受图表36小时滚动窗口清理影响。缺少长期历史的4小时、日线指标必须等待积累，不生成虚构长期K线。相同标的、周期、形态参数的信号在单批内缓存复用。

## 保险池扩容、全仓与当批强平（2026-11-03）

保险初始资本由10万改为1000万。旧保险对象第一次升级按原资本10万补入990万，先清偿未覆盖缺口，将这部分转为已赔付，剩余进入余额。capitalVersion=1标记迁移完成，重启不会再次注资。余额、资本补充量与迁移时间保存在状态；不重置玩家资金、历史赔付或K线。本次不增加信用、惩罚、还款、手续费归集等规则。

合约和条件单开仓可选isolated逐仓/cross全仓，旧仓位及旧订单缺字段时默认逐仓。同一标的同向持仓和开仓委托不能混用模式；平仓继承原模式。持仓页支持切换，需先撤销该合约委托；任何仓位风险率达到80%、处于强平中或切换后资金/风险不满足时拒绝。不改成本价、数量、现金和已有亏损。条件单切换后不静默改历史指令，触发时仍重新验证。

逐仓交易亏损含平仓费最多消耗该仓位保证金，开仓手续费另计。全仓共享未被逐仓保证金与委托冻结占用的现金，以及所有全仓浮盈浮亏；不抵押普通股票、ETF或逐仓保证金。可用金额扣除全仓浮亏，不把未实现浮盈当成可花现金。全仓组合风险率=(总维持保证金+预留平仓费)/组合权益；预计强平价假设其他标的价格不变。切换不会免除风险。

全仓在实际平亏损仓位时，先释放风险增加委托冻结，再用共享现金承担；若另有全仓浮盈可用于结算但尚未实现，应先平盈利仓位释放现金，不允许保留浮盈同时领取保险补贴。强平过程中按现金能力限制成交数量，并在其他仓位成交后继续尝试。超出该模式可承担资金的部分由保险承担，不生成玩家债务。

每分钟批次开始检查风险，每笔真实成交后立即更新该标的价格/标记价并复查；先取消风险增加委托释放冻结，必要时生成主动吃单的强平委托。系统/玩家新流动性进入时先让强平尝试成交，强平不作为极端报价挂入被动盘口。跨标的全仓风险在同批利用余下订单簿最多进行3轮补充处理；无流动性或已熔断时保留余单等后续批次，不造假成交、不自动解禁停牌、不执行10秒撮合。行情和系统交易仍每分钟一次。

标记价由原来按分钟平滑改为当批最新真实成交价，旧仓位没有成交的标的沿用原标记价直到有新成交；这是为了避免强平信号因平滑滞后。额外亏损记录和保险赔付继续在同一事务写入。

## 全市场系统盘口消失修复（2026-11-04）

旧makerBook在共享做市现金<=0时直接返回双边空盘口，造成单一资金池耗尽后所有标的看似同时停盘。已移除此全局双边撤空：买单仍按实际非负现金限制，卖单按剩余库存敞口限制，可以卖出获得现金后恢复买盘。单标的pausedUntil仍仅暂停该标的。

合约平仓实际结算的是盈亏而非现货本金，旧订单容量只检查名义买单现金/卖单库存，会漏掉系统卖方对盈利空头的赔付支出。现在按对手方可承担的净已实现盈亏再次限制成交数量；玩家对玩家成交的净系统结算也检查共享做市现金。无资金不虚构赔付，强平仍受真实流动性及结算资金约束。此修复不自动注资或清空旧负余额；旧市场可通过真实卖出回款恢复，必要时由管理员另行核对资金，不修改保险余额或玩家资产。

测试覆盖单标的熔断范围、零资金保留其他标的卖盘、真实买单补充做市现金，以及盈利空头结算不透支。仅需部署服务端market.cjs并重启mms-exchange；无需更换Toy前端。


## 熔断规则更新与自动撤单（2026-11-04）

## 防异常成交与对敲保护（2026-11-04）

新增服务端price-guard.cjs。保护参考状态在每个标的priceProtection内持久化，初始化使用最近5根已收盘历史收盘价中位数；该步骤不回滚旧成交、K线或玩家账目。每分钟价格带固定为上一保护标记价的股票/ETF±5%、雾雨币±10%，按0.1对齐。做市报价以保护参考价定位，且过滤带外报价；不再以单笔最后成交价作为做市中心。

新买/开多委托超过上界、新卖/开空委托低于下界会拒绝，远端被动限价仍可保留。旧挂单及任何候选被动成交价格在实际撮合前重新验证，带外旧玩家挂单撤回余单，已触发条件单标注取消，账本记录price-protection-cancel；系统带外报价只丢弃。强平作为主动订单同样只吃保护范围内真实报价，不虚构成交。

每笔有效成交后，按成交量权重与上一参考价锚计算加权中位标记价。股票/ETF锚权重1000份，雾雨币2000份；纯玩家对玩家成交每个账户每分钟最多贡献500/1000份权重（两个端点都扣预算，换对手和拆单不会增加同一账户预算）。涉及做市真实成交允许更高权重，系统系统也有累计权重上限；资金/库存仍由现有撮合限制。标记价不直接等于最新成交价，验证后有充分支持的价格变化仍立即检查强平。每分钟最多512个权重身份、256个价格点、128个对手组合，防状态无限增长。

熔断改为保护标记价对比其最近5分钟保护参考序列，股票/ETF20%、币30%，暂停3分钟、资讯、弹窗和撤单不变；恢复后从保护标记价重建参考点。历史K线和现价仍使用实际成交价。API显示priceBand上下界，不返回priceProtection内的账户权重和交易对手信息。

同一对账户一分钟成交达到3次时，账本生成一次counterparty-pattern-review提示，包含账户ID、笔数与数量，供管理员核查，不自动判罚、不以IP作为归属证明。现有同账户禁止自成交保留；没有可靠实名/受益人归属，因此本版不声称识别了所有小号或完全阻止多账户协同。

测试覆盖209.7旧单攻击、拆单影响上限及重启同分钟预算、有效大单/广泛参与推动标记价、保护标记价变化仍触发强平、对手重复提示与私有状态不外泄。与新规则冲突的旧测试场景已区分“最后成交价突破”与“已验证参考价突破”，不再要求单笔小额成交触发熔断或强平。

## 系统账户内部资金与库存再平衡（2026-11-04）

新增treasury.cjs，每分钟撮合开始、保护标记初始化后执行；不在轮询或每次重启时增发资本。原做市与主动交易共属系统运营方，买卖可能令现金和库存集中在不同账户。合计有钱时，单边不足不应直接解释为全市场耗尽。

若做市现金占两账户合计不足60%，从主动交易账户转账补至约80%；若主动交易现金占比不足5%，反向转账恢复20%。使用实际余额与整数分，合计现金守恒；合计非正时不凭空补钱。再平衡有滞回区间，不每分钟强行对齐比例。

单标的若做市库存达到其限额80%或主动交易库存达到其限额80%，且两系统账户库存方向相反，可按保护标记价抵销重叠部分，必须由买方实际支付现金，数量取100份整数倍。只消除内部相反敞口，不抹除外部合并净敞口，不重置库存，不改变玩家持仓。标的熔断期间不做该标的抵销。内部转账/抵销写账本system-cash-rebalance、system-inventory-netting，不算市场订单成交，不增加量/额、K线、手续费或保险收入。

新增只读脚本：node scripts/inspect-exchange-liquidity.cjs。读取同一私有市场数据库，输出系统两账户现金、合计现金、保险余额，以及每个标的库存、净敞口、库存上限、系统买卖报价量、熔断/现金/库存/价格保护限制。不会输出玩家账户或订单、不会改变市场，不要求停服。

本次针对资金分布与内部库存拥堵；如合并系统资本真正耗尽、合并净库存达到上限或无真实对手盘，不能保证始终提供双边报价。原合约清算仍应遵守有限资本和净赔付预算，不能用保险池或自动印钱掩盖持续亏损。

部署新增模块treasury.cjs、更新market.cjs及检查脚本后重启mms-exchange，下一分钟开始调配；不需要运行一次性补资工具、不需要更新Toy包。两账户资金比例取决于实际库存抵销和当批成交，不能只凭补资工具预览推断每个标的缺买盘原因。
