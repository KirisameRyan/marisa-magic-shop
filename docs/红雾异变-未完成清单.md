## 部署

默认不开启活动。先备份私有数据库，更新代码和完整资源，重启后端。确认要启动才在 /etc/mms-exchange.env 设置 MMS_INCIDENT=1；正式环境 MMS_INCIDENT_FAST=0。设置 MMS_INCIDENT=0 再重启是暂停，不是清空活动或强制复牌。恢复为1后继续原进度。不得删除线上exchange.db来重开。

本次不恢复stash中的独立合约清算资金池方案，不重置已有账户、行情或保险余额。真实多人参与度、Boss难度和结算流动性仍需要灰度观察；排行榜不能仅凭不同账户识别同一现实玩家，保留原自成交与价格保护规则。

## 2. 未完成（按优先级）

### P0 · P3 有效贡献结算

**现状**：P3A 的 Boss 伤害只来自捐款和巡逻；交易买卖不产生伤害，P2 护盘只统计“有没有净买入账户”，没有单账户上限。

**要做的规则**：

1. 只统计**实际成交**，不统计挂单；
2. 只统计**净买入**（买入 − 卖出），卖出抵消伤害，防止对倒刷伤害；
3. 禁止自成交（同一账户买卖对打）；
4. 单账户伤害设上限（建议 Boss 总血量的 10%，或每阶段 50 万伤害）；
5. P2 护盘同样按净买入 + 单账户上限，避免一个鲸鱼顶住全服目标；
6. 持仓时间加权（可选）：持有越久，有效贡献系数越高。

**建议公式**：

```
有效伤害 = min(单账户上限, 净买入名义 × 10)
```

**实现位置**：

- `tick` 成交后按 `userId` 累计 `inc.damage[userId]`；
- `applyFill` 处拿买入/卖出方向；
- `view` 暴露 `myDamage` / `damageTop`。

## 5. 已知风险

- **50 万份空头的资金**：Boss 空头是独立账本，但最终盈亏要落到保险池/系统账户，需确认上限；
- **价格保护带**：Boss 空头按 `band.lower` 卖出，不能穿价，否则玩家买不进去；
- **04:00 维护**：维护期间 `tick` 直接返回，事件 deadline 仍在走，阶段切换可能撞上维护，需要顺延；
- **停牌困住持有人**：P1 红魔停牌、P2 冰湖停牌，持仓无法平仓，需要提前公告；
- **100 倍杠杆**：P3 逼空阶段波动会放大，注意强平与保险池。
