# 幻想乡交易所：多人服务、日结与平台选择

调研日期：2026-11-01（北京时间）。本文件是方案，不表示后台、登录、排行榜或Toy接入已经实现。

## 推荐结论

先上线自建服务器小规模内测，完成权威撮合、账户账本与排行榜，再评估“Toy前端＋同一自建后台”。Toy不是替代共享交易后台的方案。

不在本轮发布、提交审核、改动现有账号或连接线上数据库。

## Toy官方资料与已核实边界

官方开发者FAQ明确：多人联机需自建后端；自有API调用需申请权限；跨用户共享KV暂未支持；Toy默认B站登录且禁止第三方登录。排行榜及云存档每Toy约50 QPS。因此不能把个人云存档作为市场账本，也不能把站点登录页面直接塞进Toy。

来源：[Toy开发者FAQ](https://www.bilibili.com/opus/1241171666570051585)，页面标题标注更新至2026-10-23，页面编辑时间显示2026-10-29。FAQ包含部分历史表述；关于共享存档，采用其明确区分“同用户跨Toy”与“跨用户共享”的说明。

官方介绍确认Toy提供网页内容承载、排行榜、云存档与视频传播入口：[Toy平台介绍](https://www.bilibili.com/toy/intro)。介绍页对“共享存档”的概括不能代替上述FAQ对跨用户能力的具体说明。

官方SDK入口：[SDK文档](https://www.bilibili.com/toy/publish/sdk)。此次公开网页读取未取得具体接口内容；服务端身份核验接口、授权凭证签发与校验、联网权限细项仍须在有权限的管理端核实并真机联调。不能预设存在某个可验签token接口，也不能将昵称、头像、浏览器上报UID或排行榜挑战当作强身份凭证。

## 每日结算：日切不等于平仓

建议业务日以北京时间04:00为边界，每日04:00生成上一业务日资产快照、收益报表和日榜。它是统计及对账边界，不是强制兑现所有持仓。

- 每分钟整点：全市场统一撮合、手续费入账、风险检查与行情发布。
- 每日04:00：按截止状态归档净值、核对资金及持仓、形成昨日榜、建立新日基准。
- 每周：生成赛季成绩。赛季初是否重置资金、赛季末仓位如何处理另行公告；每日不重置本金。

边界规则采用服务器时间和全局事件序号。先处理04:00之前应完成的事件，再记录日切快照，然后处理属于新业务日的04:00批次。不把04:00之后的新成交混入上一日。允许客户端继续接单并排队，无须为日结停市。

日切不可重新赋值入场成本、把浮盈重复计入现金，或改变逐仓保证金的风险状态。首版只收现有成交手续费；持仓费或多空资金费率需另行定义，不能临时以“日结”为名扣款。

日K仍按北京时间自然日00:00划分；04:00业务日只用于账户报表与日榜，界面分别标清。

日切任务以业务日期作为唯一键，重复运行不得重复奖励、扣费或归档。后台重启后从最后完成的批次恢复，不能重新随机一次历史行情。若维护造成长时间无法交易，恢复前先公布处置规则，不能悄悄补算大段行情并批量爆仓。

## 多人版本的权威边界

现在的JS引擎是本地练习原型；其本地模拟、云端上传存档、分数上传都不能直接成为正式多人资产系统。

服务器保存唯一市场状态和时间，运行系统交易者及新闻；客户端只提交委托、撤单、追加保证金等意图，读取服务器确认结果。

必须迁往服务器的内容：

- 钱包、冻结额、普通持仓、逐仓合约、保险金与不可改写的资金流水。
- 订单簿、事件序号、成交记录、行情、ETF持仓篮子与IOPV。
- 保证金、强平队列、停市与恢复状态。账户净值和排行榜必须使用同一套明确公布的后台估值口径。
- 用户身份、封禁、赛季、净值快照与排行榜。

浏览器只保存主题、图表周期等偏好和可丢弃缓存。正式盘不导入本地练习余额，也不能通过前端“重置练习盘”获得新本金。

## 多人会出现的主要问题

| 问题 | 需要实现的规则 |
| --- | --- |
| 同一笔钱被同时用于多个订单 | 接单时在事务内冻结资金；平仓委托同时冻结可平数量 |
| 网络重试导致重复下单或重复扣款 | 账户＋幂等键唯一；超时可查询原请求结果 |
| 两台服务器同时结算同一批 | 单市场写入者与持久化批次状态；故障接管采用隔离旧写入者的机制 |
| 截止时间争议 | 以服务端接收时间和事件序号排序；回执明确所属批次 |
| 有人离线，有人还在线交易 | 服务器持续运行，离线玩家持仓及有效委托继续受市场影响 |
| 刷新或清缓存恢复本金 | 本金发放绑定账户与赛季，数据库唯一约束；浏览器缓存不是余额来源 |
| 前端改分与改资产 | 后台自行计算所有资产和排行榜，不信任前端上传净值 |
| 自成交、多号对倒、向大号输送收益 | 禁止账户自成交；保留交易审计、关联账户异常检测和冻结审核能力 |
| 用小额成交操纵日榜或爆仓 | 对股票及ETF统一制定抗异常成交的风险估值／榜单估值规则；保留原始成交用于K线 |
| 高杠杆与集中强平 | 同账户／同标的限额、有限保险金、缺口暂停规则；没有对手盘不虚构成交 |
| 事件被提前看见或管理员操纵 | 未来事件保留服务端，发布有审计时间；管理员干预记日志，管理员不参与正式排名 |
| 视频传播突然涌入用户 | 缓存行情和榜单、限频、排队、压测；必要时分新市场，各市场独立排名 |
| 服务中断与恢复 | 持久化事件、数据库备份和可验证重放；维护期间的委托、撤单、强平处置预先公布 |

拆分市场后不能假装所有玩家仍交易同一个订单簿。第一阶段保持一个小规模共享市场，先验证一致性。

## 账户方案

仓库已经有`api/auth.php`与`api/auth-lib.php`：用户名／邮箱注册、密码哈希、登录会话、找回密码等基础代码。可以复用内部用户ID和登录体系，但接入前仍须检查部署、权限、会话与接口防护。

建议在现有用户之外新增游戏账户层，不在通用用户表中直接堆叠交易余额：

```text
通用用户 users
  ├─ 登录来源 identities（自建账号；将来可能有可核验的Toy身份）
  └─ 交易账户 game_accounts（用户、市场、赛季）
       ├─ wallets / ledger_entries
       ├─ orders / fills
       ├─ spot_positions / margin_positions
       └─ equity_snapshots / leaderboard_snapshots
```

游客可看行情、看说明、进独立练习盘；正式下单及排名需要持久化账户。一个用户每市场每赛季只领一次初始资金。救济账户可继续体验，但退出当季主榜，不允许反复领本金刷榜。

Toy版本若后续接入，先确认平台提供的身份能被本服务器可靠核验，再映射到内部用户ID。拿不到强核验能力时，Toy只提供独立体验版本，不与正式市场共享交易权限。自建站与Toy之间的账户互通必须设计明确的双方身份绑定流程；不通过传入UID或昵称自动合并账户。

## 排行榜方案

推荐先做三个榜：

1. 实时净资产榜：每分钟结算后更新，采用后台统一估值。包含普通持仓市值与合约浮盈亏，扣除适用负债；冻结资金不能再计一次。
2. 昨日收益率榜：每日04:00形成上一业务日最终成绩，日内榜标为暂定。首版要求日初已有有效账户；中途加入者次日起参与日榜。
3. 周收益榜：以周初有效账户净值为基准计算周收益率；救济、重置和管理账户不入主榜，周中加入者次周参与。是否另开统一本金、周期重置的竞赛赛季，后续单独定稿。

总资产之外展示最大回撤、强平次数等战绩维度，但不使用“最高杠杆”“成交次数”作为主要奖励依据，避免鼓励无意义刷单。

当期收益必须处理救济、奖励等非交易资金流。首版不提供排行账户外部加钱；若未来开放奖励，需明确剔除这些资金流或采用单位净值口径。只算已平仓收益会让玩家隐藏亏损仓，因此榜单必须计入持仓损益。

现有`api/leaderboard.php`接受前端提交分数并保存最高成绩。它可以提供展示参考，但不能作为交易资产榜的权威写入接口；本游戏应由后台账本直接生成榜单。

Toy榜单以后可作为经核验结果的展示镜像，是否支持可信服务端写分仍待SDK核实。本站数据库是唯一资产及排名来源，不能让两个来源互相覆盖。

## 部署选择

| 选择 | 优点 | 对这个游戏的限制 | 建议 |
| --- | --- | --- | --- |
| 自建站＋自建后台 | 身份、交易规则、数据库、恢复和榜单可统一控制 | 自己承担服务器运维与容量管理 | 第一阶段主线 |
| 仅Toy＋个人云存档 | 内容分发、个人进度和展示方便 | 不具备本方案要求的权威共享订单簿 | 只适合独立练习版 |
| Toy前端＋自建后台 | 可兼顾B站内体验与统一市场 | 需联网权限、可核验身份和容器联调；后台费用仍存在 | 第二阶段验证后接入 |

首版可从一台服务器开始：静态前端、HTTPS API、一个常驻撮合进程、事务数据库、数据库备份与日志。无需因为“多人”立即上复杂分布式集群；但撮合进程必须独立于浏览器请求持续运行。实际容量要按服务器规格和峰值订单量压测，不凭人数猜保证。

实现上优先复用现有登录；撮合后端技术栈根据服务器可运行的常驻进程、数据库及运维条件再定。是否复用SQLite或换用其他事务数据库应依据单写入架构与压力测试，不直接把JSON榜单文件当资金账本。

## 下一阶段执行顺序

1. 固定每日04:00统计边界、初始资金及榜单资格，写成玩家可读规则。
2. 实现后台账本、订单冻结、撮合事件序列、资金及持仓事务。
3. 接入现有登录；公开市场读取与认证交易接口分开。
4. 运行常驻的一分钟调度器，形成持久化行情、快照与风险事件。
5. 实现三类榜单、基础后台、审计、恢复和异常暂停。
6. 多浏览器、多账户并发验证；压测重复下单、撤单争用、故障恢复和强平缺流动性。
7. 自建站邀请内测；再检查Toy账号的联网权限与服务端身份核验，决定是否接入同一正式市场。
