# 幻想乡交易所：核心玩法与开发计划

版本：玩法设计草案 v0.3 · 2026-11-01

## 1. 产品目标与已确定方向

做一个部署在服务器上的东方 Project 主题多人交易模拟游戏。玩家交易幻想乡产业，利用新闻、产业关联和盘口判断行情，通过做多、做空及有限杠杆参与市场。

已确定：

- 所有玩家进入同一市场，系统和玩家订单共同决定成交价。
- 采用粗时间粒度批量撮合；下单期间接收请求，截止时集中执行。现以60秒为默认批次，支持配置其他间隔用于压测，最终由压测与试玩决定。
- 每批可以在多个价位成交，不采用每批统一成交价的集合竞价。
- 持仓跨批次保留，不到点强制平仓。
- 系统保留企业经营、世界事件、突发事件，影响通过经营数据和系统订单传递。
- 仅使用游戏币；首版不接入充值兑换、提现或现实资产。

核心体验：读懂异变线索 → 选择产业和方向 → 按盘口安排进出 → 承受波动和资金成本 → 在预期兑现或失效时退出。

## 2. 为什么要持续玩

短期：每批检查订单成交、盘口和保证金，决定挂单、撤单、减仓或继续持有。

中期：围绕持续数十分钟到数小时的新闻链布局，寻找被误读的消息、产业轮动和情绪过热。

长期：参加暂定七天的赛季，积累战绩、解锁称号与外观，形成自己的交易风格。赛季长度为待试玩参数。

频繁盯盘应提供更精细的交易机会，但普通玩家也应能通过低杠杆、限价单和保护单参与。不得用签到倍率、付费情报或永久属性加成决定交易优势。

## 3. 首发市场与东方主题

首发四个产业，集中玩家流动性，不一次推出大量冷门标的。

| 标的 | 经营驱动 | 常见机会与风险 |
| --- | --- | --- |
| 河童重工 | 技术、订单、原料、水利 | 新设备订单增长；故障、洪水和交付延期 |
| 守矢能源 | 发电、工程、信仰需求 | 项目投产；事故、成本上涨和需求不及预期 |
| 永远亭制药 | 药品需求、研发、供应 | 疫病与新药；研发失败和供应中断 |
| 红魔商事 | 红茶、宴会、夜间消费 | 红雾与宴会；运输受阻和经营支出扩大 |

角色是新闻来源、企业经营者和系统交易者的叙事载体。东方元素必须改变经济关系，例如能源成本上涨会增加河童制造成本，而不只是给随机涨跌换皮。

## 4. 交易产品与订单

首版交易“产业合约”，界面明确显示“合约／模拟交易”。它跟踪幻想乡产业价值，价格主要由本市场成交产生；不把它假称为具备借股、分红等完整规则的现货股票。

| 操作 | 订单方向 | 作用 |
| --- | --- | --- |
| 开多 | 买 | 增加多头 |
| 平多 | 卖 | 减少多头 |
| 开空 | 卖 | 增加空头 |
| 平空 | 买 | 减少空头 |

成交必须有对手订单。多头开仓可匹配空头开仓，也可以匹配其他多头的平仓卖单；持仓账本按双方开平动作更新。禁止账户与自己成交。

首版每账户、每标的采用单向净持仓，避免同时持有多空两套仓位。反向操作先减仓；要反向开仓须明确提交新开仓指令。平仓单采用只减仓规则，不能意外翻成反向持仓。

首版提供：

- 限价单：指定价格和数量，允许部分成交，余量保留或取消。
- 带价格保护的立即成交单：下一批在允许范围内吃单，未成交部分取消，不提供无边界市价单。
- 撤单：显示待确认与已撤销状态，按服务器顺序确定是否赶上本批截止。
- 条件止盈止损：达到触发条件后进入下一可执行批次；触发不代表保证成交，不承诺按触发价成交。
- 逐仓保证金：每个仓位单独分配保证金；默认不自动动用钱包资金救仓。

用户界面首版使用整数“份”，避免“手”的换算负担；如以后使用手，必须全局固定合约乘数。

## 5. 批量撮合规则

服务器持续接收订单，做身份、余额、持仓、限额和幂等校验，冻结所需保证金或待平数量。行情和持仓以最后已结算批次为准，未执行订单明确标为待撮合。

截止时封存批次，以服务器分配的事件序号回放本批新增、撤销等指令。买单匹配最低可成交卖价，卖单匹配最高可成交买价；同价按进入订单簿顺序成交，成交价取簿内被动挂单价。剩余有效订单延续到下一批。

因此需要区分“请求已接受”与“交易已成交”。某个挂单如果在回放中已经被更早指令成交，之后的撤单只能撤销剩余数量；前端必须让玩家理解该语义，不能把待撤显示为已撤。

新指令进入下一批，不能在结算过程中改变已封存批次。系统订单使用同一排序规则，不能插队；系统生成器按预设日程运行，不能读取本批未公开玩家订单后临时决定报价。

示例：卖盘101.1有100份、101.2有200份、101.3有500份，足量买单依次吃完，成交均价101.25，最后价101.3。下批沿用101.3作为上一成交参考，下一笔成交仍由实际盘口决定。

批次流程：封存输入 → 按序撮合与记账 → 更新估值和保证金 → 处理风险队列 → 保存一致性检查与快照 → 发布结果。风险处理如产生新成交，要继续更新受影响账户；设置有界处理和暂停机制，不能无限递归。

## 6. 系统如何生成行情

维护三个不同数值：

1. 产业参考价值：企业经营、产业关联和事件共同产生的估值锚，用于系统交易者决策；不是成交价，也不保证市场回归。
2. 最后成交价：实际订单成交结果，用于交易记录和图表。
3. 风险标记价格：用于浮动盈亏、保证金与条件单触发的独立规则化价格，避免极少量异常成交决定爆仓。

经营数据按事件节奏变化，不必每次订单都重算。首版可采用基准价值加经营因子的简化模型，事件分阶段改变收入、成本、产能和风险，设置合理上下界，避免随机游走到负值。

系统交易者以规则生成分层订单，不需要为每个虚拟居民运行智能体：

| 类型 | 决策 | 约束 |
| --- | --- | --- |
| 做市商 | 在自己的估值附近双边挂单，按库存偏移报价 | 有资金、仓位、每批数量上限；高风险时扩大价差 |
| 价值交易者 | 偏离估值足够大才入场 | 资金有限，估值有误差，不能无限兜底 |
| 趋势交易者 | 根据历史已结算价格追随趋势 | 仓位和追价上限，可能亏损退出 |
| 日常交易流 | 小额、多样的交易需求 | 固定总预算，避免无意义刷量 |

系统持仓、盈亏和资金流全部入账。赛季初配置资金，补充预算时作为明确的系统经济规则记录，禁止亏损后静默无限加钱。撮合服务不能为保证某个价格而凭空创建对手方。

系统不能同时知道事件未来结果并交易获利。交易者按已经释放的信息行动；事件随机结果与交易决策隔离，记录随机种子和版本以便复盘。

## 7. 玩家与系统的平衡

主要调节变量是盘口深度、报价间距、库存容量和价值回归资金，而不是给系统与玩家分配固定涨跌百分比。

目标：普通玩家能影响局部成交，大单能推动短期价格，持续经营变化影响中期估值。极端单边行情允许出现，但不允许靠无限系统资金随意兑现利润。

初期提供足够系统深度；随着真实成交增加，逐日或逐赛季缓慢减少系统依赖。不能在某个玩家下单后针对该订单调整难度。流动性不足时适当扩大价差、降低允许开仓规模，而非假装任何数量都能成交。

观察指标：玩家与系统成交占比、盘口价差、指定金额订单的冲击、系统库存集中度、无成交批次占比、财富集中度与强平损失。目标区间通过模拟制定，首稿不伪造精确平衡数值。

## 8. 新闻与事件：主要策略来源

事件采用“征兆—公开进展—兑现／反转—后续恢复”的新闻链。每条新闻有时间、来源、已知事实和不确定部分。

示例：守矢大型能源项目。

- 征兆：公开传出建设计划，能源预期改善。
- 扩散：河童设备订单增加，设备制造受益。
- 风险：施工延期、成本超支或信仰不足，收益可能无法兑现。
- 兑现：投产结果公布；若市场已经提前炒高，即使成功也可能获利回吐。

消息先发布，再留出完整交易窗口，相关系统交易者按同一公开时间线反应。突发事件允许跳变，但首版限制跨产业同时冲击与连续灾难，避免持仓完全取决于抽签。

《文文。新闻》承担快讯；角色对白解释不同立场。首版不售卖有确定交易优势的私密情报，不允许玩家自由发布看起来像官方公告的消息。

## 9. 杠杆、强平与离线

初始方案：1倍、2倍、3倍；新手默认1倍，先完成教学才开放更高倍数。具体参数和最小保证金由压力模拟验证。

盈亏按合约数量、乘数和价格差计算；杠杆只影响建立该数量仓位需要的保证金，不重复乘在盈亏上。费用包括明确展示的交易手续费与简化持仓费用，均进入系统账本；首版不额外引入复杂多空资金费率。

风险标记价格建议以历史成交的平滑价格为主体，结合可信深度的盘口中价和独立产业参考进行异常偏离检测。精确公式、权重、样本不足时的降级规则须在开放杠杆前确定并公开。参考价值不能因为新消息瞬间跳变，就直接让用户被强平。

账户达到维持保证金线，先取消增加风险的订单，再进入部分或全部强平。强平订单同样需要对手盘；下一批执行或专用有限风险阶段执行的选择，在实现前固定。没有流动性时不能按屏幕价虚构平仓。

预设保险资金、单账户与单标的仓位上限。保险不足时暂停该标的新开仓并按公布的故障处置规则处理缺口，禁止静默把损失转给其他玩家。缺口分摊规则未确定前，不开放高杠杆。

离线持仓照常变化，保护单继续有效。首次开杠杆明确展示这一点。未来可提供低杠杆休闲市场，但首版先集中一个市场。

## 10. K线、页面与反馈

价格图来自真实成交，不补画虚构波动。一个批次有多笔成交，可按实际执行顺序计算批次OHLC；无成交批次显示零成交量，并明确价格沿用上一成交值。批次内部顺序不是实际墙钟时间内的连续行情，不能画出假装逐秒成交的细节。

首版页面：

- 市场总览：四个产业、最近价格、成交量、新闻、下一批倒计时。
- 交易页：K线、买卖盘口、下单、预估成交范围、持仓和保证金。
- 订单页：待撮合、已接受入簿、部分成交、已成交、待撤、已撤和拒绝原因。
- 新闻页：事件时间线、产业关联、经营数据。
- 资产页：钱包、冻结额、已实现／浮动盈亏、费用、净值曲线。
- 赛季页：净资产榜、满足最低参与条件的收益榜、最大回撤和称号。

同屏展示最后成交价与风险标记价，解释二者用途。估算成交量和价格必须注明基于上一已公布盘口，不能承诺下一批成交。

## 11. 赛季、成长与新手

暂定七天一个赛季，同一起始资金，结算后保留历史战绩与外观。赛季末停止新开仓，提前公告结束窗口；剩余仓位采用事先公布的终局结算规则，不能临时更改价格。

新手用练习账户完成限价单、部分成交、开空、平仓与保证金教学。破产后可领取救济资金继续体验，但该账户本赛季不再参与主榜；避免反复重置本金冲榜。

奖励以称号、头像框、交易记录卡为主，不提高成交优先级、不降低个人交易成本。最大回撤作为战绩维度，首版不做容易被小额操作刷分的复杂综合积分。

## 12. 服务器与公平性

建议由单一市场写入者处理同一市场的批次，数据库事务维护订单、成交和资产账本。价格用整数最小价位，资金用定点数，禁止浮点误差累计。

基本要求：订单幂等键、服务端事件序号、批次编号、不可重复扣款、崩溃重放、结算完成后统一发布。截止以服务器时间为准；网络慢的请求明确进入下一批。

批量撮合减轻持续计算与广播，但不消除接单和记账成本。未压测前不承诺服务器容量。限制单账户请求频率和有效挂单数量，前端使用快照与增量更新，不高频轮询全量账本。

反滥用：禁止自成交，检查关联账户对刷、异常资金转移、极小成交操纵收盘和撤单洪泛。采用公开的价格保护范围与异常暂停机制；保护范围内的挂单也不保证成交。

## 13. 分阶段实施

### 阶段一：无界面的可复现市场原型

一个标的、两个玩家账户和一个有限资金做市商；完成订单、批次撮合、部分成交、撤单、账本和事件日志。先使用1倍，不开放杠杆。

验收：101.1／101.2／101.3示例能准确重放；撤单竞态结果确定；重复请求与崩溃恢复不重复成交；玩家及系统资金、仓位变化均可核对。

### 阶段二：可玩的交易闭环

接入四个产业、交易页面、真实成交K线、公开新闻链、系统交易者和资产历史。验证低人数时能成交，高人数时玩家确实能改变行情。

验收：模拟无人、单人、多人及单边订单场景；系统库存不会无限增长，价格来源可以复盘。

### 阶段三：杠杆与风险处理

加入逐仓、净持仓、2／3倍、标记价格、条件单、强平队列、保险与异常暂停。

验收：测试跳空、流动性枯竭、连续强平、系统做市商亏损和保险不足。验证不存在保证金重复使用和只减仓单反向开仓。风险规则未通过，不开放高倍数。

### 阶段四：赛季与封闭测试

加入教学、榜单、救济、管理员事件与风险面板。压测目标人数和订单峰值，在60秒与120秒间选择更合适的节奏。

验收：结算时间明显短于批次间隔；重启可恢复；玩家能理解待撮合、未成交与风险价；通过真实试玩决定事件频率和系统流动性参数。

## 14. 首版暂不做与待定项

暂不做：完整现货借股市场、期权、玩家发币、跨市场套利、公司经营、自由发公告、付费信息优势、复杂角色养成。

实现前还需固定：批次间隔、合约乘数与价格精度、同批撤单展示、风险标记公式、维持保证金、强平执行阶段、保险不足处置、终局结算、服务端技术栈及首轮目标人数。

下一步先完成阶段一的规则与数据模型，再做交易页原型。先证明市场能正确运行，再扩展美术、剧情和标的数量。

## 15. UI参考与首个交互原型

用户提供三张证券App截图作为基础格局参考：行情详情、账户总览、持仓列表。采用黑灰底、细分隔线、紧凑数值、红涨绿跌、固定底部导航。行情页保留顶部报价摘要、左侧图表和右侧五档盘口；账户页保留资产摘要和快捷操作；持仓页保留数量、成本、现价与盈亏对照。东方主题体现在产业名称、印章与新闻，不以装饰遮挡数据。

入口：`gensokyo_exchange.html`。首版为独立本地练习原型，具备四产业切换、分时／批次K、盘口点价、限价多空、逐仓1／2／3倍、部分成交、撤单、平仓、资产／成交记录、本地保存和新闻页。图表复用仓库已有ECharts，无需外部CDN。

本地原型的边界：单账户与系统报价撮合，不是多人交易服务器；每批刷新系统报价后按用户订单顺序执行，与最终生产版完整事件回放不同。初始历史是明确标注的演示数据；无任何实际成交时不伪造新成交。风险处理仅提供简化减仓队列，不具备完整保险和穿仓处理。条件单、排行榜、用户登录及后台事件管理尚未实现。页面关闭或隐藏后模拟暂停。

## 17. v0.3：统一一分钟、扩充标的与保证金风控

本节覆盖v0.2的10秒系统交易规则。系统与玩家均只在分钟整点撮合；移除10秒图表入口，存量细粒度行情汇总为分钟OHLCV，现有资产、持仓与订单继续保留。

标的扩为8只股票（原四只加白玉楼文旅、天狗传媒、地灵矿业、命莲物流）与幻想乡产业ETF。提供完整下拉选择和可滚动标签。ETF篮子初始按8股等权配置，之后保持每ETF份额对应的成分股数量不变，权重随市价浮动。IOPV＝各成分股固定数量×最新成交价之和；ETF成交价由独立盘口决定。展示当前折溢价、成分股、份额与权重，历史IOPV沿对应时间的成分股收盘价计算，不拿当前估值回填整条历史。本版无申购赎回。IOPV概念参考基金发行人说明：https://www.proshares.com/faqs/finding-proshares-intraday-values-iopvsiivs 。

图表增加MA5／10／20／30，使用所选周期的收盘价，样本不足处不画线；ETF额外显示IOPV虚线。MACD保留。为控制浏览器存储体积，本地保留约36小时分钟数据，长周期样本不足明确提示。

合约新开仓杠杆为2／3／5／10／20倍；原有1倍合约只保留平仓兼容。以下均为本游戏规则，不对应真实券商统一标准：

- 初始保证金率＝1÷杠杆。逐仓权益＝已分配保证金＋按标记价计算的浮动盈亏。
- 当前保证金率＝逐仓权益÷当前名义金额。维持保证金率设为1%，额外预留名义金额0.05%的平仓费。
- 风险率＝（维持保证金＋预留平仓费）÷逐仓权益；80%预警并限制增加合约风险，100%进入只减仓的强平队列。
- 展示初始／当前／维持保证金率、仓位权益、维持金额和预估强平标记价。强平价格是阈值估计，不保证成交。
- 支持从可用资金追加逐仓保证金，不改变仓位数量和入场成本。恢复安全后撤销尚未成交的强平余单。强平单不能直接手动撤销。
- 强平仍消耗真实对手盘；流动性不足则保留队列。模拟隔离仓损失以分配保证金为上限，跳空缺口记入初始100,000游戏币的保险金；保险不足明确记录未覆盖缺口并停止合约新开仓，不无限补钱。服务端全账户风控仍需后续实现。
