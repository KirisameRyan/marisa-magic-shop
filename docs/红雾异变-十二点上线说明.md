## 网站后端

先把完整服务器增量包覆盖到 /www/wwwroot/www.azureflame.cloud，保留私有数据库和 /etc/mms-exchange.env，不重新运行安装脚本。

在服务器执行：

```bash
cd /www/wwwroot/www.azureflame.cloud
node scripts/schedule-redmist-release.cjs
node scripts/schedule-redmist-release.cjs --apply
sudo systemctl restart mms-exchange
sudo systemctl status mms-exchange --no-pager
```

第一条脚本只检查；--apply 会先在站外备份两份数据库及原环境文件，再写入：

```ini
MMS_INCIDENT=1
MMS_INCIDENT_FAST=0
MMS_INCIDENT_START_AT=2026-11-05T12:00:00+08:00
```

提前重启不会提前启动活动。到点由现有每秒调度器在整分钟撮合时启动P1，不需要cron。若配置时间已过，则重启后开始；已有活动只恢复，不会重置或重开已结束活动。维护暂停不会被此脚本擅自清除。

重启后 /api/exchange.php?route=health 的 release.startsAt 应是 1793851200000；12点前 active=false，12点后新P1启动时 active=true。原市场健康状态应为 halted=false。不要删除exchange.db，不要覆盖线上私有数据库，也不要把本地演示目录上传。
