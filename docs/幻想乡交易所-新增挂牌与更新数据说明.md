## 更新时保留什么

服务器从其 `MMS_PRIVATE_DIR/exchange.db` 恢复已有市场。重启时只为缺失的新标的初始化数据，不重新导入本地预览的初始行情文件。已测试九标的旧库升级：原股票逐根K线、账户余额、123份旧仓、101份旧委托、ETF成分、初始导入标记及资金流水均保持不变；再次重启不重复添加股票或发放本金。

`initial-market.json` 仅供全新交易库首次启动使用，更新此文件不会覆盖已有库。新股补入自己的初始演示行情。原有36小时K线滚动保留规则仍然生效，这种正常过期清理与上传覆盖不同；本次不扩展历史行情的保留期限。

只同步代码或使用构建包，不上传 `var/`、`_local/`、`site.db`、`exchange.db` 及 `-wal/-shm` 文件。不要删除或替换服务器上的数据库。自定义私有目录必须继续使用原路径；改变 `MMS_PRIVATE_DIR` 可能让服务读到另一个库。

## 更新前备份

可在服务器项目目录运行：

```sh
node scripts/backup-exchange.cjs
```

默认读取项目 `var/private`（或终端环境中设置的 `MMS_PRIVATE_DIR`），备份到当前用户家目录的 `mms-exchange-backups/` 下。自定义路径时使用：

```sh
node scripts/backup-exchange.cjs /实际私有目录 /root/mms-exchange-backups
```

脚本创建独立目录，用SQLite生成一致的单库快照，包含已提交的WAL数据，校验后生成 `complete.json`，不会覆盖源数据库或旧备份，并拒绝把备份放到网站代码目录中。两个库按交易库、账户库顺序分别备份，并非跨库原子备份；需要严格统一的维护时点时，应先暂停相关写入。

备份完成后更新代码，在服务器执行 `systemctl restart mms-exchange`，再检查健康接口。不要为了看到新股而删除旧库。超过5分钟的服务中断仍会触发原有维护暂停规则。
