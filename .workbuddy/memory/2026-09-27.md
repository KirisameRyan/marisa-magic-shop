## 魔理沙幸存者 v2 改造方案（未改码，已交付文档）

背景：DeepSeek 已按 v1 方案完成改造（HTML 306→388 行、JS 3764→4144 行；stage/fitStage/drawHUD/暂停Tab/开始页立绘均已落地，质量尚可）。用户实测后提出 4 个新反馈，我复测并产出 v2 方案文档：`D:/Marisa_Project/marisa_survivor_改造方案_v2.md`。

用户四大反馈 → 方案：
1. fitStage 固定 16:9 填充有黑边 → 动态逻辑分辨率：H=540 恒定、W=540×aspect（>1600 封顶），竖屏(aspect<1)退回 960×540 letterbox；canvas 物理 1:1；stage-ui 尺寸随 W/H 动态；HUD_SCALE=min(1.6,max(1,1.05/s)) 解决小屏字小。
2. 固定摇杆手感差 → 悬浮摇杆：落点即基准点，R=56 逻辑单位，死区 6，仅 active 时绘制，前 6 秒引导提示。
3. 误触页面滑动 → overscroll-behavior:none + wrap touch-action:none（overlay pan-y）+ 局内 touchmove 恒 preventDefault + body.ingame 隐藏 #shopNav（主方案，iOS/微信通用）+ Fullscreen API/orientation.lock（Android 增强，全 try/catch）。
4. 实测新 bug：pauseBtn 未按 gameState 显隐（开始页裸露）、横屏暂停面板继续按钮被挤出（pause-box 需 flex column + pz-body flex:1）、暂停键触摸会穿透激活摇杆（e.target 排除）、刷怪半径硬编码 640/520/620 需改半对角线公式、Boss 入场 y-620 改 -(H/2+90)、Boss 条 W<1000 时下移防与 HP 条重叠、排行榜输入框键盘遮挡（低优先）。

技术要点（供后续会话参考）：
- spawnEnemy 刷怪半径 640+rand*120 是按 960×540 半对角线≈551 设计的，视口变宽必须改 `Math.sqrt(W*W+H*H)/2+60`。
- camX/onScreen/fillRect(W,H)/drawBgLayer 都是每帧读 W/H，动态化天然兼容。
- startGame() 总由按钮点击触发 → 可在其内部 requestFullscreen（满足用户手势要求）。
- agent-browser 的 set device 无法模拟 pointer:coarse，旋转遮罩/摇杆只能真机验证。
- 本地预览服务器 8643 端口（8642 的旧进程已挂）。
